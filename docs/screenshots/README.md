# Product screenshots

This folder is reserved for screenshots captured from the running ExamFlow application. Do not add AI-generated mockups, recreated dashboards or screenshots from an outdated deployment and label them as the live product.

## Capture checklist

Capture the deployed application after the complete production UI has been visually verified.

| Filename | Screen | What the capture should demonstrate |
|---|---|---|
| overview.png | Overview dashboard | Session summary, KPI cards, API connection state and issue indicators |
| schedule.png | Schedule | Real assignment rows with exam, date, room and invigilator information |
| exams.png | Exams | Exam catalogue, requirements and lifecycle/status information |
| rooms.png | Rooms | Room capacity, equipment and accessibility details |
| invigilators.png | Invigilators | Staff records and availability context |
| conflicts.png | Conflicts | Actionable conflict and unassigned-exam explanations |
| validation.png | Validation | Hard-constraint validation summary and findings |
| reports-exports.png | Reports & Exports | Metrics and available export formats |
| audit-trail.png | Audit Trail | Timestamped events and traceable schedule activity |

## Capture standards

- Capture the real deployed UI at a consistent desktop viewport (recommended 1440 × 1000).
- Use representative demo records; never expose real student personal information, access tokens, email addresses or secrets.
- Keep the browser chrome out of the image where possible.
- Use PNG for crisp text and tables.
- Do not edit values, hide errors or fabricate success states.
- Re-check the live app before replacing an existing screenshot.

Once captures are added, embed the overview and the most important workflow screens in the root README using relative paths such as docs/screenshots/overview.png.
